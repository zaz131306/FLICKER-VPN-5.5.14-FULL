  Работает в поле, подтверждено этим дампом (правками не тронуто):
     • stop-ack: шесть смен ноды подряд — ни одного «dbg: proxy=none» между
       switch и connected;
     • смена режима маршрутизации без рестарта туннеля (smart → all в 22:04:09);
     • autoPort + сверка порта (1080 занят → хост слушает 1081 → перевооружение);
     • рейтинг только по VPN-нодам (1805), локальные транспорты отдельно;
     • восстановление из тупика: лестница ходит по нодам сама, карусели нет.

  A. Браузер был вооружён на порту, где никто не слушает (главный дефект).
     Шапка дампа 22:00:10: узел «Диагностика (direct)», статус connected,
     «прокси вооружён 127.0.0.1:1080», host SOCKS «не слушает». Для локального
     транспорта native host не поднимается и SOCKS-слушателя нет в принципе, но
     applyProxyModeNow() вооружала ручной прокси на STATE.socksPort, а
     perRequestDecision() гнала пер-реквест трафик туда же. Плюс
     handleVerifyResult() «подтверждал» туннель, которого нет.
     Теперь: protocol === "direct" (не DPI) → DIRECT до всякой маршрутизации;
     отдельная идемпотентная ветка local-direct в applyProxyModeNow()
     (setProxyNone, tunnelVerified = true, proxyMode = "local-direct",
     журнал local-direct, broadcastUI directNode); verify для локального
     транспорта — no-op.

  B. HOLD держал мёртвый порт и продлевался пробным прогоном.
     22:04:09 verify «туннель больше не подтверждён» → HOLD; 22:04:17 старт
     пробы 600 серверов; пока хост её жевал, ветка probeRunning() на каждом
     цикле вызывала markHoldProgress(«хост занят пробой серверов»), окно без
     прогресса (120 c) не закрывалось — и браузер сидел на 1080, где никто не
     слушал, до 22:06:06. Держать мёртвый порт — то же самое, что выбросить
     прокси, только без интернета.
     Теперь: endpointDead() = локальный транспорт ИЛИ native host не на связи
     ИЛИ последний diagnose сказал socksListening=false (свежесть 60 c); при
     endpointDead() удержание запрещено (canHold/wantHold), прокси
     освобождается сразу, в журнале hold-refused, в логе хоста
     «proxy: HOLD отменён (…) — мёртвый порт не держу»; проба прогрессом на
     мёртвом конце не считается. HOLD на живом конце не тронут: окно без
     прогресса 120 c, потолок 300 c — постоянной дыры в интернете нет.

  C. Мёртвые ноды не определялись никогда.
     22:06:47 и 22:07:34: «контрольный dial … socks5: connect отклонён (код
     0x1)» → «tunnelAlive=false проигнорирован (SOCKS слушает, подряд 1,
     трафик есть)». Правило 5.5.10 требовало 3 отказа подряд + 45 c + нулевой
     трафик: серия обнуляется при каждой смене ноды (а ноды менялись каждые
     20–40 c), а «нулевого трафика» не бывает — контрольные запросы самого
     расширения идут через туннель (в шапке ↑0.00 ↓0.00 MB и рядом «трафик есть»).
     Теперь вердикт по ДВУМ независимым подтверждениям: на tunnelAlive=false
     расширение само гоняет контрольный запрос браузера через SOCKS. Не прошёл
     → declareSoftDead() сразу (без 45 c, без нулевого трафика, без трёх
     отказов) → нода в мёртвые, лестница уходит на другую. Прошёл → нода
     рабочая, dial хоста игнорируем и пишем об этом в лог. Прежнее мягкое
     правило сохранено как запасной путь и зовёт ту же declareSoftDead()
     (кулдаун внутри, журнал soft-dead, noteTunnelDeath, recoverFromDeadTunnel).

  D. Панель больше не врёт.
     statusPayload.proxyBlockedReason — почему прокси не вооружён; dbg при смене
     режима печатает фактический STATE.proxyMode; в диагностике options.js:
     «Прокси браузера: не вооружён ← выбран локальный транспорт (НЕ VPN),
     трафик идёт напрямую (<причина>)».

  Честно о том, что расширением не чинится: проба дала 32 живых из 600 (~5 %),
  в рейтинге доверенных 0, мёртвых 50, без истории 1755. Это состояние подписки
  провайдера. 5.5.14 не оживляет мёртвые ноды — она перестаёт выдавать их за
  живые, определяет смерть за секунды и уходит с них сама.
